# SQL bundles (historical; not currently paste-ready)

> **Do not apply these bundles.** The checked-in files are stale, and regenerating them has not been verified as a safe upgrade or a clean client installation. Hosted migration history differs from the repository and includes combined migrations; do not blindly use `supabase db push`. The manual apply-migrations workflow on this branch is disabled and fails closed; older revisions may still be dispatchable and must not be used. The older instructions below are retained for review only, not a current deployment procedure. See `docs/CLIENT_CHANGE_PLAN.md` for current status and required rehearsal.

| File | Use it when | Apply with |
| --- | --- | --- |
| `preflight.sql` | **first, always** — reports what is applied, the next step, and the two ordering dependencies | Supabase SQL editor (read-only) |
| `fresh-install.sql` | the project has no BALE tables yet | Supabase SQL editor |
| `upgrade-hardening.sql` | the base schema exists, and the hardening / AI / Bale-request changes do not | Supabase SQL editor |
| `verify-live.sql` | always, after either bundle | Supabase SQL editor (read-only) |
| `seed-cleanup.sql` | the demo seed was applied — §1 rotate, §2 force re-auth, §3 delete | Supabase SQL editor |

`preflight.sql` and `seed-cleanup.sql` are hand-written and safe to re-run.
The two `*-install.sql` / `*-hardening.sql` bundles are generated; never
hand-edit them — regenerate instead. The upgrade bundle now also carries the
Founder-reviewed Bale request migration for already-migrated projects.

⚠️ **Order matters.** `20260929000000_communications.sql` must be applied
before `upgrade-hardening.sql`, and the two bundles are mutually exclusive.
`preflight.sql` tells you which you need and whether the ordering is satisfied.

Generated by `scripts/build-apply-sql.mjs` (`npm run build:apply-sql`) from
`supabase/migrations`. Never hand-edit — regenerate instead. Each bundle's
header lists its source files and their SHA-256.

The demo seed is deliberately excluded from both bundles: it creates real auth
accounts with a published password. See `docs/SECURITY.md` §9.

Full procedure, including the pre-flight query that tells you which bundle you
need: `docs/MIGRATION_RUNBOOK.md`.
