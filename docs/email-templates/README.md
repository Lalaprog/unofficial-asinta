# Supabase Auth email template

**`SUPABASE_MAGIC_LINK.html` is the copy-and-paste HTML for Authentication → Email Templates → Magic Link.** It is not the app's invoice email template and is not installed automatically.

1. In Supabase, open **Authentication → Email Templates → Magic Link**. Copy the entire contents of `SUPABASE_MAGIC_LINK.html` into the HTML/message body, replacing that template's existing body. Do not paste it into the subject or into Reset Password.
2. Suggested subject: `Your Asinta sign-in code`. Keep the `{{ .Token }}`, `{{ .ConfirmationURL }}`, and `{{ .SiteURL }}` placeholders exactly as written; Supabase fills them in. Never paste an actual code, password, or secret into the template.
3. Save. This changes the Magic Link email for the entire Supabase Auth project, including other consumers of that template. The link is intentionally retained for compatibility. The email code and link are alternative ways to use the same one-time request; link scanners can sometimes consume a link before a person does.
4. The eight separate boxes are used when the token is eight characters, matching the currently configured OTP length. If that setting changes, the template safely displays the complete code in one box instead. A complete copyable code is always printed below the boxes.
5. The email-code feature remains disabled until the rollout steps and hosted checks in `../EMAIL_CODE_RECOVERY_ROLLOUT.md` are complete. Test with an owner-controlled address only when ready; merely saving the template does not prove SMTP delivery. Email apps may render fonts, corners, or spacing differently.

The header uses a PNG derived from the app’s official `public/brand/asinta-emblem.svg`. Supabase fills in `{{ .SiteURL }}` using the project’s **Authentication → URL Configuration → Site URL**. Set it to the publicly reachable app origin without a trailing slash (for example, `https://example.com`) and ensure that deployment includes `public/brand/asinta-emblem-email.png`. `localhost`, a protected preview, or a deployment missing the PNG cannot serve the image to recipients. If the URL changes, update it in Supabase; emails already sent retain the old URL. If no Site URL is supplied, the logo is omitted. Some mail clients block remote images until the reader permits them; the brand text, code and link remain readable if the image is blocked. Like other remote email images, loading it may generate ordinary website access logs; its URL contains no token or recipient identifier.
