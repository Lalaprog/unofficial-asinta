# Older-pay project cost compatibility — development hold

This describes the candidate on PR #104, not an installed migration or a launch approval. Older vouchers use a separate, reviewed project split; they do not become weekly paid allocations and the original payroll or Bale is not changed. Saved ordinary/cross-site reviews are only components and must not be substituted for the legacy-inclusive total.

## Checks completed

- In the isolated SQL/UI chain, an older automatic client with no saved review continues to see a positive unallocated-voucher signal after a separate legacy split. Its automatic total remains hidden. The updated reader can suppress that global warning only after verifying the split, and only shows an automatic amount for a site with no applicable split or incoming older-voucher correction. This relies on the ordinary coverage definition and on the normal writer never inserting weekly allocations for an already-paid unallocated voucher.
- Read-only development catalog inspection confirmed that the only function with an ordinary weekly-allocation INSERT is `weekly_worker_payment_internal`, not executable directly by API roles. Its reviewed definition requires a source-bound weekly voucher; for an already-paid voucher it validates existing allocations and returns without inserting. Authenticated, anon and service roles had no table or column write grants on the eight inspected weekly-allocation, case, correction and corrected/cross-site review relations. These are point-in-time observations, not a guarantee against privileged database users or future schema changes.
- A PostgreSQL 17 CI test now uses the real older-voucher inventory, corrected-source, preview, review and attribution SQL in an empty synthetic database. If the split commits first, a review of the old snapshot is rejected; if the review commits first, a later split makes its next read stale. This covers those two writer directions, not all writers or production load.
- The guarded old saved-review RPC and real attribution writer were also checked on PostgreSQL 17, including insufficient-assurance/private-reader denial. A mixed SQL/UI chain tests ordinary and incoming cross-site reviews alongside older pay and prevents adding the same correction twice.
- The updated summary fails closed whenever any older split is reported changed, including when a separate ordinary saved review exists and the automatic-cost feature is off. Review screens state that their ordinary component excludes older-voucher splits.
