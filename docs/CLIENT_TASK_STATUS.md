## Cross-cutting release blockers

- Do not merge the draft as complete or blindly run `supabase db push` or the stale generated apply bundles. Hosted migration history differs from the repository.
- Preview backend identity and real authenticated Auth/PostgREST/device behavior have not been established. Passing synthetic fixtures, rollback simulations, CI or a READY build is not proof of a working production workflow. The branch checks retry records before sending, confirming or explicitly clearing worker moves, rental links, and the gated historical-worker assertion and attribution entries. These tab-local checks are not atomic cross-tab locks and cannot prevent cleared storage, concurrent requests or same-origin scripts from creating uncertainty. Investigate outcomes before taking another action.
- Development migration `20261114072124_development_revoke_service_finance_truncate` removed effective service-role TRUNCATE on expenses, payment dates and weekly paid allocations. Migration `20261114072708_development_revoke_service_paid_evidence_writers` also removed direct service INSERT/UPDATE/DELETE on the two paid-evidence tables, preserving their SELECT and the Founder payment RPC. Migration `20261114094409_development_revoke_anonymous_workforce_finance_privileges` removed effective anonymous table/column access to payroll, advances, advance requests and attendance after synthetic and hosted rollback checks. It preserved existing authenticated/service ACL entries and all policies; selected authenticated column privileges remain. RLS already blocked anonymous rows. These changes do not establish actual hosted Auth/PostgREST, all owner/definer paths, maintenance or old-client compatibility. See the writer observations.
- The Bale scheduler has no independent failure/dead-man alert. This may be configured after system adjustments, but is required before real use.
- No verified backup exists. A reliable recovery and restore test covering database, Auth and Storage is required before real client data or handover. The user handles backup/handover later and accepts disposable development data, not loss of client records.
- The user handles real-account/device testing, environment variables and SMTP; no additional fictional hosted records, real payments or messages are authorized without separate approval.
- The manuscript is not currently in scope. Preserve the explicit future-only status of Supervisor expense submission.

The old and post-attribution corrected-review bundles and the cross-site development bundle now contain installed objects and must not be rerun against development.
