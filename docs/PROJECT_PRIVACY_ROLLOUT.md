## What changes

A role-aware, read-only `visible_projects()` function returns complete project information to Founders and assigned sites with `client_id` and `budget_estimate` redacted to other assigned users. The app uses it for project reads. Founder project writes return public columns, then re-read the authoritative project through that function; if the re-read fails, the app warns the user that the write may already have succeeded.

After the app is live and old tabs refreshed, the second migration removes direct authenticated SELECT access to the two sensitive columns for **both roles** and grants access to the other known project columns. Founder access to those two fields is through the function instead. Direct `select('*')` on `projects` will fail for authenticated clients, including Founder integrations and stale tabs. Service-role clients remain privileged; site names, addresses, older cached data and other routes may still contain identifying information. This is not a complete privacy audit. The function's security depends on the existing `is_founder()` and `is_supervisor_assigned()` helpers being correct and on its owner having appropriate permissions.

The shared session cache is versioned by user and role; other users’ and roles’ cached ledgers and the legacy role-agnostic cache are removed on sign-in; ledger caches are removed on sign-out. This does not erase information already downloaded by old app sessions or other tools. End-to-end behavior of real-time subscriptions and hosted PostgREST under column grants must be checked; SQL tests alone do not establish it.

The generated fresh-install bundle includes both phases for new empty installations. The upgrade-hardening bundle deliberately excludes them so an existing app is not unexpectedly broken by that bundle; existing installations require the coordinated sequence above.
