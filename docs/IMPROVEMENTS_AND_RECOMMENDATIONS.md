## Free automatic-reminder scheduling — revisit later

- [ ] **Try the existing Supabase Free project first:** Supabase documents a built-in scheduler that can make scheduled web requests. It may be able to wake the app's existing reminder endpoint without a separate paid service. Confirm the project's actual availability and limits, secure the request, and test it in isolation before choosing or enabling it. [Supabase scheduling guide](https://supabase.com/docs/guides/functions/schedule-functions).
- **Practical limits:** A Free Supabase project can pause after low activity, so reminders would not run while it is paused. A missed run may delay a reminder; automatic catch-up must remain cautious rather than promise exact delivery. Sending SMS or email may also have provider charges or limits, even if the scheduler itself is free. [Supabase project pausing](https://supabase.com/docs/guides/platform/free-project-pausing).
- **Alternative:** Vercel's Schedules beta documents a Hobby option, but its availability for this project and shared usage limits are unverified. GitHub Actions could be investigated as a fallback, but scheduled runs can be delayed or dropped and private repositories have usage limits; it is not a guaranteed free or punctual solution. [Vercel Schedules limits](https://vercel.com/docs/schedules/limits), [GitHub scheduled workflows](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule).
- **Hosting terms are separate from the scheduler:** Vercel describes Hobby as personal, non-commercial use. Before using the app for actual firm business, check whether the hosting plan permits that use and consider a suitable no-cost host if necessary. Changing only the scheduler does not resolve hosting eligibility. [Vercel Hobby plan](https://vercel.com/docs/plans/hobby).
- No scheduler has been installed or activated. Keep automatic reminders OFF, and obtain separate approval before hosted changes or real messages. Continue the outstanding security, historical-data and provider checks in `REMINDER_ROLLOUT_NOTES.md` before any rollout.

## Later recommendations — not scheduled for implementation now

- **IT troubleshooting tracker:** Consider a private, low-maintenance place for technical status, failed integrations, model identifiers and actionable diagnostics. Decide access and format before building; never expose credentials or sensitive financial data. It should not add clutter to the Founder's ordinary screens.
- **Multiple-receipt queue:** If entering several receipts becomes frequent, consider selecting multiple photos and processing one at a time with separate review. Current draft storage supports one expense draft, not a durable queue. Design safe partial failure and recovery before adding it.
- **Supervisor updates:** Project-assignment replacement is atomic, but the profile, Auth metadata, roster and audit updates remain separate operations. Unconfirmed results require checking the account and assignments before retrying.
- **Financial consistency:** The invoice email preview is rechecked before sending, but that check does not lock the invoice against a change during delivery. Expense writes and their audit entries are separate. Stronger transaction and retry safeguards, including more robust concurrent-tab handling and invoice payment protections, remain useful future work. Existing protections reduce risk but do not make every workflow atomic.
- **Project photo cleanup:** Replacing or deleting a photo attempts to clean up the old object, but an interrupted operation, uncertain database response or project deletion can leave private unused files. Consider a carefully checked orphan cleanup after the feature is proven; never delete photos referenced by a project or an in-flight update. Review future Storage policies carefully: a broad permissive policy could expose private buckets.
- **Receipt storage cleanup:** Discarded or interrupted drafts can leave unused private receipt objects. Any future cleanup must avoid deleting objects referenced by a recorded expense or an in-flight write.
- **Security and recovery checks:** Continue reviewing low-assurance sessions, storage access, recovery choices and future policies. Automated local simulations are not a substitute for hosted Auth/Storage and real-device checks.
- **Operational backups and historical reconciliation:** Verify backups include both database and private objects, and reconcile historical payroll/Bale data before relying on it. Do not reset or delete records without an explicit request.
