# Optional Supervisor portrait — experimental candidate, not installed

The Founder Team Accounts page contains a **default-off** experimental control. A Founder can select a JPEG, PNG or WebP, replace it or remove it; the hard-hat icon remains if no portrait exists. The browser scales the selected image before upload (maximum selection 20 MB / 80 million pixels, output up to 512 px and 256 KiB). Photo management is separate from account creation and does not alter roles, assignments or pay. With the same flag, an assured Supervisor can see their own portrait in the account menu and profile; it is fetched privately and falls back to the icon on errors. Changes made by a Founder may require the Supervisor to reload or navigate before appearing. This is not connected device testing.

The uninstalled SQL draft stores one bounded portrait directly in a private database table rather than a public Storage bucket. Only the Founder or that Supervisor can call the read RPC; only a Founder can write, with session assurance. It revokes direct access from client roles and checks selected inherited permissions; owners, database administrators, backups and other privileged paths can still access it. Do not confuse this with absolute secrecy. Images in database backups need appropriate protection and retention; old backups may retain removed portraits. The removal is a versioned tombstone, and deleting the user cascades the row. Changing the role hides the image but does not erase it; converting the profile back to Supervisor would reveal it again. Review retention and account lifecycle before use.

The candidate locks profile rows, rejects non-READ-COMMITTED transactions, checks image type signatures and size, and uses a version plus operation ID for optimistic concurrency and exact retry of the latest operation. Signature checks do not fully decode or sanitize arbitrary image content; server-side decoder hardening and request-body limits need review. If a response is ambiguous the UI offers a retry with the same operation or a refresh. Pending operation state is in component memory only: reload, navigation or a closed tab loses it. An error is not proof that a write failed. Do not upload sensitive images until failure, retention and recovery are reviewed.

PGlite exercises selected permissions, assurance, fallback, version conflicts/retries, deletion and input checks; mocked UI tests exercise upload and failure flows and account-switch/assurance transitions. A disposable PostgreSQL 17 fixture additionally checks simultaneous saves and retries, removal versus replacement, one Founder demotion and repeatable-read rejection. These tests are not a hosted schema clone or real Auth/PostgREST, device, image decoding, accessibility, all authorization changes or all lock-race tests. Profile lock ordering, inherited function/table privileges, existing triggers, owner/service-role paths, rate and body limits, backups, and role-change semantics require review. The draft does not contain an audit trail. There is no hosted database or feature-flag change in this batch. Never install it via an old migration bundle or enable `NEXT_PUBLIC_SUPERVISOR_PORTRAIT_PREVIEW` on a shared or production deployment without an independently reviewed, tested installation and recovery plan; the public build-time flag is not authorization or a schema check.
