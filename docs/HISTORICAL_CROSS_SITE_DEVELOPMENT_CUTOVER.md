## Additional safety observations

Local PostgreSQL 17.6 tests now run the exact installed artifact and the real inventory chain in an empty disposable database. An ordinary review held a real expense insert until commit, after which freshness changed; a concurrent uncommitted expense caused the save to time out with no review row, and the old inventory was rejected after the expense committed. Rollback also released a waiting insert without retaining a review. Non-Founder, insufficient-assurance, anon and service calls and direct authenticated review-table deletion were denied in the fixture.

A deliberately reversed lock-order test reproduced a deadlock between a Founder-row update and an ordinary review: PostgreSQL aborted one transaction and the other succeeded, with no partial review in that test. Thus the existing 3-second timeout/deadlock detection protects atomicity in that case but does **not** establish smooth operation under contention or cover all lock orders. The fixture has simplified RLS and artificial data. A hosted point-in-time catalog inspection found the ten historical/case/attribution/review tables owned by postgres with RLS and no table-level API-role write privileges; a separate inspection found no API-role column INSERT/UPDATE grants and listed enabled immutable guards. These observations do not cover definer/owner/service paths comprehensively or prove real authenticated behavior.

The branch's production-target build guard now requires `NEXT_PUBLIC_HISTORICAL_CASE_BINDING_PREVIEW=true`, because the installed database no longer permits the legacy attribution RPC. This guard applies only when building the checked-in guarded branch with its normal build command; it cannot change old deployments, block privileged clients or prove that the backend matches. It does not enable the separate cross-site flags or authorize release.
